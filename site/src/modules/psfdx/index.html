MODULE REFERENCE / psfdx

psfdx

Core commands

Authentication, org management, SOQL, records, data import/export and Salesforce CLI administration.

Get started

PS> Install-Module psfdx
PS> Import-Module psfdx
PS> Get-Command -Module psfdx

There is only one PowerShell Gallery package: psfdx. Importing it loads the entire module suite, while each command retains its owning module name.

Examples

1. Connect to your sandbox

PS> Connect-Salesforce -Sandbox

2. Explore built-in help

PS> Get-Help Select-SalesforceRecords -Full
NAME
    Select-SalesforceRecords

SYNOPSIS
    Runs a Salesforce SOQL query and returns PowerShell objects.

SYNTAX
    Select-SalesforceRecords -Query <String> [-TargetOrg <String>] ...

DESCRIPTION
    Query Salesforce records with SOQL.

    ... additional parameters and examples omitted ...

Illustrative excerpt, shortened for readability. Run the command to view the complete installed help.

3. Export Salesforce records to CSV

PS> Select-SalesforceRecords `
    -Query 'SELECT Id, Name FROM Account LIMIT 10' `
    -TargetOrg myorg |
    Export-Csv -Path './accounts.csv' -NoTypeInformation

4. Update the entire suite

PS> Update-Module psfdx

Discover every command and parameter

Use Get-Command -Module psfdx to list the core cmdlets or Get-Command -Module 'psfdx*' to list all modules after Import-Module psfdx. PowerShell's built-in help includes descriptions, parameters, examples and the underlying sf mapping.

Command reference

Authentication and aliases

Add-SalesforceAlias

Description

Stores the alias in the Salesforce CLI configuration on this computer; nothing changes in the org. Once set, the alias works anywhere a psfdx cmdlet takes -TargetOrg.

Syntax

Add-SalesforceAlias -Alias <string> -TargetOrg <string>

Parameters

-Alias string, required
The alias to create, for example prod or dev1. Setting an alias that already exists replaces it. Required.
-TargetOrg string, required
Username, or an existing alias, that the new alias should point to. Required.

Example

PS> Add-SalesforceAlias -Alias dev1 -TargetOrg user@example.com.dev1

Create the alias dev1 for that username.

Salesforce CLI

Runs sf alias set.

Connect-Salesforce

Description

Opens the login page of Salesforce in your browser. After you sign in, the Salesforce CLI stores the authorization on this computer so other psfdx cmdlets can use the org. Use -Sandbox for a sandbox, or -CustomUrl for a My Domain or other login URL.

Syntax

Connect-Salesforce [-Sandbox] [-CustomUrl <string>] [-Alias <string>] [-SetDefault] [-SetDefaultDevHub] [-Browser <string>] [-OAuthClientId <string>] [-ClientApp <string>] [-Scopes <string>] [-Username <string>]

Parameters

-Sandbox switch
Log in through the sandbox login host. psfdx passes --instance-url https://test.salesforce.com. Use -CustomUrl instead for a different host.
-CustomUrl string
URL of the instance that the org lives on. Passed to sf as --instance-url.
-Alias string
Alias for the org. Passed to sf as --alias.
-SetDefault switch
Set the authenticated org as the default that all org-related commands run against. Adds --set-default.
-SetDefaultDevHub switch
Set the authenticated org as the default Dev Hub. Adds --set-default-dev-hub.
-Browser string
Browser in which to open the org. Passed to sf as --browser. Valid values: chrome, edge, firefox.
-OAuthClientId string
OAuth client ID (also called consumer key) of your custom connected app. Passed to sf as --client-id.
-ClientApp string
Name that saves this login as a separate authorization for the same user, so you can log in to one org with more than one connected app. Passed to sf as --client-app. Use the same name with Disconnect-Salesforce -ClientApp to log it out.
-Scopes string
OAuth scopes to request, separated by spaces, for example "api web refresh_token". Passed to sf as --scopes. Use it with your own connected app (-OAuthClientId).
-Username string
User name to log in as, which pre-fills the login page. Passed to sf as --username.

Example

PS> Connect-Salesforce -Alias prod -SetDefault

Log in to production, give the org the alias prod and make it the default target org.

Salesforce CLI

Runs sf org login web.

Connect-SalesforceAccessToken

Description

Runs sf org login access-token. Give the org's instance URL and the access token as a SecureString. The token is handed to the CLI in the SF_ACCESS_TOKEN environment variable of the sf process only, never on the command line, and the variable is put back to its earlier value afterwards. The login is saved on this computer so other psfdx cmdlets can use the org. The authorization cannot be refreshed, so it stops working when the token expires. Because the environment belongs to the whole process, logins started at the same time in one PowerShell process run one after the other. The URL must be an absolute https URL, because the token is sent to it. Tokens and authorization URLs are removed from the result.

Syntax

Connect-SalesforceAccessToken -InstanceUrl <string> -AccessToken <Security.SecureString> [-Alias <string>] [-SetDefault] [-SetDefaultDevHub] [-NoPrompt]

Parameters

-InstanceUrl string, required
URL of the org, for example https://mycompany.my.salesforce.com. Must be an absolute https:// URL. Passed to sf as --instance-url. Required.
-AccessToken Security.SecureString, required
The access token, as a SecureString, for example (Read-Host -AsSecureString). Passed to sf in the SF_ACCESS_TOKEN environment variable. Required.
-Alias string
Alias for the org. Passed to sf as --alias.
-SetDefault switch
Set the authenticated org as the default that all org-related commands run against. Adds --set-default.
-SetDefaultDevHub switch
Set the authenticated org as the default Dev Hub. Adds --set-default-dev-hub.
-NoPrompt switch
Don't prompt for confirmation, for example before overwriting an existing login. Adds --no-prompt.

Example

PS> Connect-SalesforceAccessToken -InstanceUrl https://mycompany.my.salesforce.com -AccessToken (Read-Host -AsSecureString) -Alias ci -NoPrompt

Log in with a token that you type at the prompt.

Salesforce CLI

Runs sf org login access-token.

Connect-SalesforceApi

Description

Does not use the Salesforce CLI. It posts the user name, the password plus security token, and the connected app client ID and secret to the org's /services/oauth2/token endpoint with Invoke-RestMethod and returns the response, which holds the access token and instance URL. The request is sent only over https. Pass the password, token and client secret as SecureString: they are converted to text only when the request is built and are never written to the verbose, debug or error output. Plain strings still work but write a warning, because they stay in your session history and memory.

Syntax

Connect-SalesforceApi -TargetOrg <string> -Password <object> -Token <object> -ClientId <string> -ClientSecret <object> [-Sandbox] [-CustomUrl <string>]

Parameters

-TargetOrg string, required
The Salesforce user name to log in as (sent as the OAuth username). This is not an org alias. Required.
-Password object, required
The user's password, as a SecureString (preferred) or a plain string (deprecated, writes a warning). The security token is appended to it. Required.
-Token object, required
The user's security token, as a SecureString (preferred) or a plain string (deprecated, writes a warning). Appended to the password. Required.
-ClientId string, required
Consumer key of the connected app used for the login. Required.
-ClientSecret object, required
Consumer secret of the connected app, as a SecureString (preferred) or a plain string (deprecated, writes a warning). Required.
-Sandbox switch
Use the sandbox login host https://test.salesforce.com instead of https://login.salesforce.com.
-CustomUrl string
Base URL of the login host to use instead, for example a My Domain. It must be an absolute https:// URL, otherwise the cmdlet stops before sending anything.

Example

PS> Connect-SalesforceApi -TargetOrg user@example.com -Password $pw -Token $tok -ClientId $key -ClientSecret $secret

Request an access token from production.

Connect-SalesforceAuthUrl

Description

Runs sf org login sfdx-url with the file you give. The result has the access token and auth URL removed unless you pass -IncludeToken. Keep the file safe: anyone who has it can log in as that user.

Syntax

Connect-SalesforceAuthUrl -SfdxUrlFile <string> [-Alias <string>] [-SetDefault] [-SetDefaultDevHub] [-IncludeToken]

Parameters

-SfdxUrlFile string, required
Path to a file that contains the Salesforce DX authorization URL. Passed to sf as --sfdx-url-file. Required.
-Alias string
Alias for the org. Passed to sf as --alias.
-SetDefault switch
Set the authenticated org as the default that all org-related commands run against. Adds --set-default.
-SetDefaultDevHub switch
Set the authenticated org as the default Dev Hub. Adds --set-default-dev-hub.
-IncludeToken switch
Return the CLI result as it is. Current CLI versions do not return tokens or auth URLs for this command, so this may change nothing. Without it psfdx removes accessToken, refreshToken, sfdxAuthUrl, password, clientSecret and privateKey from the result.

Example

PS> Connect-SalesforceAuthUrl -SfdxUrlFile .\auth.txt -Alias ci -SetDefault

Log in from the file and make the org the default.

Salesforce CLI

Runs sf org login sfdx-url.

Description

Runs sf org login jwt with the connected app's consumer key, the user name and the private key file. It is meant for CI. The key file must exist; its content is never read or printed by psfdx. The login host is https://login.salesforce.com, or https://test.salesforce.com with -Sandbox.

OAuth client ID (also called consumer key) of your custom connected app. Passed to sf as --client-id. Required.
-TargetOrg string, required

Path to a file containing the private key. Passed to sf as --jwt-key-file. Required.
-Sandbox switch
Log in at https://test.salesforce.com. psfdx always passes --instance-url: production by default, the sandbox host with this switch.
-Alias string
Alias for the org. Passed to sf as --alias.
-SetDefault switch

Set the authenticated org as the default Dev Hub. Adds --set-default-dev-hub.

Example

Disconnect-Salesforce

Description

Runs sf org logout. The authorization is removed from this computer; scratch orgs and sandboxes are not deleted. Asks for confirmation and supports -WhatIf.

Syntax

Disconnect-Salesforce -All [-NoPrompt]

Parameters

-All switch, required
Log out of every org this computer is authorized for. Use it instead of -TargetOrg. Required in the All parameter set.
-TargetOrg string, required
Username or alias of the target org. Passed to sf as --target-org. Required in the TargetOrg parameter set.
-ClientApp string
Name of the client app login to log out of, the name given to Connect-Salesforce -ClientApp. Passed to sf as --client-app. Use it with -TargetOrg.
-NoPrompt switch
Don't prompt for confirmation. Adds --no-prompt.

Example

PS> Disconnect-Salesforce -TargetOrg dev1 -WhatIf

Show what would happen without logging out.

SOQL helpers

ConvertTo-SalesforceSoqlDateTime

Description

Formats a DateTime as a SOQL datetime literal in UTC, for example 2026-11-18T11:00:00Z. It is not quoted.

The value is converted to UTC before the Z is written, so the literal is the same instant whatever the machine's time zone: Kind Utc used as it is Kind Local converted from the machine's local time zone, including daylight saving time Kind Unspecified treated as local time, the same as .NET's ToUniversalTime() does. A date parsed from text such as '2026-11-18 12:00' is Unspecified, so it means 12:00 where you are. -TimeZone names the zone to read a Local or Unspecified value in instead of the machine's. A time that does not exist in that zone (the hour skipped when the clocks go forward) is refused. A time that happens twice (the hour repeated when the clocks go back) is read as standard time, as .NET does. Fractions of a second are dropped, as the old 's' format did. 's' is culture-invariant.

Syntax

ConvertTo-SalesforceSoqlDateTime -Value <datetime> [-TimeZone <TimeZoneInfo>]

Parameters

-Value datetime, required
The date and time to format. A Local or Unspecified kind is read as local time and converted to UTC. Accepts pipeline input. Required. Accepts input from the pipeline.
-TimeZone TimeZoneInfo
Time zone to read an unspecified value in, for example Europe/London, instead of the computer's zone.

Example

PS> ConvertTo-SalesforceSoqlDateTime -Value my-org

Runs ConvertTo-SalesforceSoqlDateTime with its required parameters.

ConvertTo-SalesforceSoqlIdentifier

Description

Checks that a value is a plain Salesforce object or field API name (letters, digits and underscores, starting with a letter, with optional dots for relationships) and returns it. Identifiers cannot be quoted in SOQL, so anything else is refused instead of being placed in the query.

Syntax

ConvertTo-SalesforceSoqlIdentifier -Value <string>

Parameters

-Value string, required
An object or field API name (letters, digits and underscores, with optional dots for relationships). Anything else makes the cmdlet throw. Accepts pipeline input. Required. Accepts input from the pipeline.

Example

PS> ConvertTo-SalesforceSoqlIdentifier -Value my-org

Runs ConvertTo-SalesforceSoqlIdentifier with its required parameters.

ConvertTo-SalesforceSoqlLiteral

Description

Turns a value into a quoted SOQL string literal that is safe to place in a generated query.

SOQL escapes a string with a backslash, not by doubling the quote: O'Brien is 'O\'Brien'. Backslash, apostrophe and double quote are escaped. Line breaks, tabs, backspace and form feed become \n \r \t \b \f, so a value never puts a real line break into the query. Any other control character is refused rather than guessed at. Unicode text is kept as it is.

With -Like, % and _ are escaped as well so they match themselves; without it they are left alone, because they are ordinary characters in an = comparison.

The result is also safe inside the double-quoted --query "..." argument that psfdx builds: a double quote or a backtick gets the command-line escape that ConvertTo-PsfdxArgumentList understands. Caller-authored queries passed to Select-SalesforceRecords -Query are not touched by this.

Syntax

ConvertTo-SalesforceSoqlLiteral -Value <string> [-Like]

Parameters

-Value string, required
The text to turn into a quoted SOQL string. Quotes and backslashes are escaped; control characters other than line breaks and tabs are refused. Accepts pipeline input. Required. Accepts input from the pipeline.
-Like switch
Also escape % and _ so they match themselves inside a LIKE pattern.

Example

PS> ConvertTo-SalesforceSoqlLiteral -Value my-org

Runs ConvertTo-SalesforceSoqlLiteral with its required parameters.

Records and data

Export-SalesforceTreeData

Description

Each -Query is a SOQL query; a query with a subquery exports parent and children together. The queries go to the CLI unchanged, so use one line and no double quotes (the Windows CLI shim rejects line breaks and double quotes in an argument). Without -Plan the records are returned in Records and the CLI writes one JSON file per query. With -Plan the CLI writes one file per object and a plan file that references them, which Import-SalesforceTreeData -Plan reads; Files and PlanFile hold their paths. The CLI creates -OutputDirectory if it does not exist.

Syntax

Export-SalesforceTreeData -Query <string[]> [-Plan] [-Prefix <string>] [-OutputDirectory <string>] [-TargetOrg <string>]

Parameters

-Query string[], required
One or more SOQL queries whose records, with the related records they select, are exported. Each query is passed as its own --query. A query with a parent-to-child subquery exports the children too. Required.
-Plan switch
Generate multiple sObject tree files and a plan definition file for aggregated import. Adds --plan.
-Prefix string
Prefix of generated files. Passed to sf as --prefix.
-OutputDirectory string
Directory in which to generate the JSON files; default is current directory. Passed to sf as --output-dir.
-TargetOrg string
Username or alias of the target org. Not required if the `target-org` configuration variable is already set. Passed to sf as --target-org.

Example

PS> Export-SalesforceTreeData -Query "SELECT Id, Name, (SELECT Id, LastName FROM Contacts) FROM Account WHERE Name LIKE 'Acme%'" -Plan -OutputDirectory .\data -TargetOrg source
PS> Import-SalesforceTreeData -Plan .\data\Account-Contact-plan.json -TargetOrg scratch

Salesforce CLI

Runs sf data export tree.

Get-SalesforceRecord

Description

Select the record with -Id, or with -Where, a hashtable of field values that identify exactly one record (the CLI reports an error for none or for several). They are alternatives: the CLI accepts only one. The record is returned as an object of its fields, without the internal attributes property. A value in -Where is passed to the CLI as Field='value'; because the CLI has no way to escape a quote inside a value, a value that contains a single quote, a double quote or a line break is refused. For anything more complex use Select-SalesforceRecords. A record that does not exist makes the cmdlet throw the CLI's message.

Syntax

Get-SalesforceRecord -Type <string> -Id <string> [-UseToolingApi] [-TargetOrg <string>]
Get-SalesforceRecord -Type <string> -Where <IDictionary> [-UseToolingApi] [-TargetOrg <string>]

Parameters

-Type string, required
API name of the Salesforce or Tooling API object that you're retrieving a record from. Passed to sf as --sobject. Required.
-Id string, required
ID of the record you're retrieving. Passed to sf as --record-id. Required in the ById parameter set. Alias: RecordId. Accepts input from the pipeline by property name.
-Where IDictionary, required
List of <fieldName>=<value> pairs that identify the record you want to display. Passed to sf as --where. Required in the ByFields parameter set.
-UseToolingApi switch
Use Tooling API so you can retrieve a record from a Tooling API object. Adds --use-tooling-api.
-TargetOrg string
Username or alias of the target org. Not required if the `target-org` configuration variable is already set. Passed to sf as --target-org.

Example

PS> Get-SalesforceRecord -Type Account -Id 001xx000003DGb2AAG -TargetOrg myorg

Runs sf data get record.

Import-SalesforceTreeData

Description

Give either -Plan (a plan file from Export-SalesforceTreeData -Plan) or -File (one or more tree JSON files), not both. Asks for confirmation only when $ConfirmPreference is Medium or lower, and -WhatIf makes no CLI call. Returns one object per record created: RefId, Type and Id. Syntax

Import-SalesforceTreeData -Plan <string> [-TargetOrg <string>]
Import-SalesforceTreeData -File <string[]> [-TargetOrg <string>]

Parameters

-Plan string, required
Plan definition file to insert multiple data files. Passed to sf as --plan. Required in the Plan parameter set.
-File string[], required
Comma-separated and in-order JSON files that contain the records, in sObject tree format, that you want to insert. Passed to sf as --files. Required in the Files parameter set.
-TargetOrg string
Username or alias of the target org. Not required if the `target-org` configuration variable is already set. Passed to sf as --target-org.

Example

PS> Import-SalesforceTreeData -Plan .\data\Account-Contact-plan.json -TargetOrg scratch

Search-SalesforceRecords

Description

Runs sf data search with --query or --file. SOSL searches the text fields of several objects at once, for example FIND {Acme} IN ALL FIELDS RETURNING Account(Id, Name), Contact(Id, Name). With the default -ResultFormat json the records are returned as objects without their attributes property, each with an SObject property that holds the object it came from; no match returns nothing (wrap the call in @() for an empty array). With human or csv the CLI text is returned as it is. A bad search throws the CLI message. Invoke-SalesforceRestRequest

Description

Runs sf api request rest, which calls any REST endpoint as the user you are logged in as, so you need no token. The response is returned as text, or as an object with -AsObject. A request that changes data (POST, PUT, PATCH or DELETE) asks for confirmation and supports -WhatIf; a read does not. An error response makes the cmdlet throw (PsfdxRequestFailed). Give the body as -Body, as a file with -BodyFile, or give the whole request (URL, method, headers and body) in a JSON -File. On Windows the CLI's .cmd launcher cannot take a body with a double quote, which JSON always has, so use -BodyFile or -File there. For the other psfdx REST helpers see Invoke-SalesforceApi, which uses an access token instead.

Invoke-SalesforceRestRequest [-Url <string>] [-Method <string>] [-Body <string>] [-BodyFile <string>] [-File <string>] [-Header <IDictionary>] [-Include] [-StreamToFile <string>] [-AsObject] [-TargetOrg <string>]

The endpoint, for example /services/data/v62.0/limits. Not needed if -File holds it. It is an argument of the command, not a flag.
-Method string
HTTP method. Valid values: GET, POST, PUT, PATCH, HEAD, DELETE, OPTIONS, TRACE. The CLI default is GET. Passed to sf as --method.

The request body as text. Use one of -Body, -BodyFile and -File. Passed to sf as --body.
-BodyFile string
Path of a file that holds the request body. It must exist. The cmdlet sends it as --body @path. Use one of -Body, -BodyFile and -File.
-File string

-Header IDictionary
HTTP headers as name and value pairs. Each is passed to sf as its own --header name:value. Names are checked and a value may not contain a line break. Passed to sf as --header.
-Include switch
Include the HTTP status and headers in the output. Cannot be used with -StreamToFile or -AsObject. Adds --include.
-StreamToFile string
Write the response to this file instead of returning it. Cannot be used with -Include or -AsObject. Passed to sf as --stream-to-file.
-AsObject switch
Return the response converted from JSON instead of text.
-TargetOrg string
Username or alias of the target org. Not required if the `target-org` configuration variable is already set. Passed to sf as --target-org.
