MODULE REFERENCE / psfdx-shared

psfdx-shared

Shared implementation helpers

Reusable functions used across the psfdx modules; documented for transparency but not the main public API.

Part of the psfdx package, which installs every module: see the installation and update instructions.

PS> Get-Command -Module psfdx-shared

Commands

ConvertTo-SalesforceSoqlDateTime

Description

Formats a DateTime as a SOQL datetime literal in UTC, for example 2026-11-18T11:00:00Z. It is not quoted.

The value is converted to UTC before the Z is written, so the literal is the same instant whatever the machine's time zone: Kind Utc used as it is Kind Local converted from the machine's local time zone, including daylight saving time Kind Unspecified treated as local time, the same as .NET's ToUniversalTime() does. A date parsed from text such as '2026-11-18 12:00' is Unspecified, so it means 12:00 where you are. -TimeZone names the zone to read a Local or Unspecified value in instead of the machine's. A time that does not exist in that zone (the hour skipped when the clocks go forward) is refused. A time that happens twice (the hour repeated when the clocks go back) is read as standard time, as .NET does. Fractions of a second are dropped, as the old 's' format did. 's' is culture-invariant.

Syntax

ConvertTo-SalesforceSoqlDateTime -Value <datetime> [-TimeZone <TimeZoneInfo>]

Parameters

-Value datetime, required
The date and time to format. A Local or Unspecified kind is read as local time and converted to UTC. Accepts pipeline input. Required. Accepts input from the pipeline.
-TimeZone TimeZoneInfo
Time zone to read an unspecified value in, for example Europe/London, instead of the computer's zone.

Example

PS> ConvertTo-SalesforceSoqlDateTime -Value my-org

Runs ConvertTo-SalesforceSoqlDateTime with its required parameters.

ConvertTo-SalesforceSoqlIdentifier

Description

Checks that a value is a plain Salesforce object or field API name (letters, digits and underscores, starting with a letter, with optional dots for relationships) and returns it. Identifiers cannot be quoted in SOQL, so anything else is refused instead of being placed in the query.

Syntax

ConvertTo-SalesforceSoqlIdentifier -Value <string>

Parameters

-Value string, required
An object or field API name (letters, digits and underscores, with optional dots for relationships). Anything else makes the cmdlet throw. Accepts pipeline input. Required. Accepts input from the pipeline.

Example

PS> ConvertTo-SalesforceSoqlIdentifier -Value my-org

Runs ConvertTo-SalesforceSoqlIdentifier with its required parameters.

ConvertTo-SalesforceSoqlLiteral

Description

Turns a value into a quoted SOQL string literal that is safe to place in a generated query.

SOQL escapes a string with a backslash, not by doubling the quote: O'Brien is 'O\'Brien'. Backslash, apostrophe and double quote are escaped. Line breaks, tabs, backspace and form feed become \n \r \t \b \f, so a value never puts a real line break into the query. Any other control character is refused rather than guessed at. Unicode text is kept as it is.

With -Like, % and _ are escaped as well so they match themselves; without it they are left alone, because they are ordinary characters in an = comparison.

The result is also safe inside the double-quoted --query "..." argument that psfdx builds: a double quote or a backtick gets the command-line escape that ConvertTo-PsfdxArgumentList understands. Caller-authored queries passed to Select-SalesforceRecords -Query are not touched by this.

Syntax

ConvertTo-SalesforceSoqlLiteral -Value <string> [-Like]

Parameters

-Value string, required
The text to turn into a quoted SOQL string. Quotes and backslashes are escaped; control characters other than line breaks and tabs are refused. Accepts pipeline input. Required. Accepts input from the pipeline.
-Like switch
Also escape % and _ so they match themselves inside a LIKE pattern.

Example

PS> ConvertTo-SalesforceSoqlLiteral -Value my-org

Runs ConvertTo-SalesforceSoqlLiteral with its required parameters.

Get-PsfdxCommonParameterSplat

Description

Shared helper used by every psfdx cmdlet. It returns a hashtable holding the common parameters the caller was given (such as Verbose and Debug, and WhatIf and Confirm) so they can be splatted into Invoke-Salesforce, which makes -Verbose show the sf command. It is public only because the modules import it from psfdx-shared; it may change without notice. It does not run sf.

Syntax

Get-PsfdxCommonParameterSplat -BoundParameters <IDictionary>

Parameters

-BoundParameters IDictionary, required
The caller's $PSBoundParameters. Required.

Example

PS> $commonParams = Get-PsfdxCommonParameterSplat -BoundParameters $PSBoundParameters

Inside a cmdlet.

Get-SalesforceApexCliTestArguments

Description

Returns a string array containing --test-level and, where applicable, repeated --tests flags for Apex classes. Resolves specified, referenced, or folder-based Apex tests locally. This helper builds arguments; it does not run a deployment. Test-level mapping: NoTests=NoTestRun, SpecificTests/ReferencedTests/TestsInFolder= RunSpecifiedTests, TestsInOrg=RunLocalTests, TestsInOrgAndPackages= RunAllTestsInOrg, RelevantTests=RunRelevantTests.

Syntax

Get-SalesforceApexCliTestArguments [-SourceDir <string>] [-TestLevel <string>] [-Tests <string[]>]

Parameters

-SourceDir string
Apex source file for ReferencedTests; folder or file whose directory is searched for TestsInFolder. If omitted with TestsInFolder, uses current directory.
-TestLevel string
Test selection mode. Default: NoTests. Valid values: NoTests, SpecificTests, ReferencedTests, TestsInFolder, TestsInOrg, TestsInOrgAndPackages, RelevantTests. ReferencedTests requires SourceDir; SpecificTests requires non-empty Tests.
-Tests string[]
Apex test class names when TestLevel is SpecificTests. Blank values are removed and duplicates deduplicated for that mode. Emits one --tests flag per name.

Example

PS> Get-SalesforceApexCliTestArguments -TestLevel SpecificTests -Tests AccountServiceTest,ContactServiceTest

Produces --test-level RunSpecifiedTests with two --tests arguments.

Get-SalesforceApexTestClassNamesFromPath

Description

Searches recursively for .cls files containing the literal @isTest marker, returning unique file base names sorted alphabetically. If Path is a file, searches from its parent directory instead. Throws if the path does not exist. An empty search returns an empty array.

Syntax

Get-SalesforceApexTestClassNamesFromPath -Path <string>

Parameters

-Path string, required
Existing folder or file whose parent folder is searched recursively.

Example

PS> Get-SalesforceApexTestClassNamesFromPath -Path './force-app/main/default/classes'

Lists the Apex test classes discovered under the classes directory.

Invoke-Salesforce

Description

Shared helper that every psfdx cmdlet uses to run a program. It runs -FilePath directly with the -Arguments array (never through Invoke-Expression or a shell), so ; | & and $(...) in a value are plain text. With -Verbose it prints the command with secret option values masked. In JSON mode a failed process without a JSON body throws; a failed process with a JSON body is returned so Show-SalesforceResult can report its message. The older -Command string form is still accepted. The executable is found on the PATH at run time. Public because the modules import it from psfdx-shared; it may change without notice.

Syntax

Invoke-Salesforce -Command <string>
Invoke-Salesforce -FilePath <string> [-Arguments <string[]>] [-Interactive]

Parameters

-Command string, required
Legacy form: one command string that is split into the program and its arguments. Do not use it in new code. Required in the Command parameter set.
-FilePath string, required
The program to run, usually sf. It is looked up on the PATH. Required in the Arguments parameter set.
-Arguments string[]
The arguments, one array element each, exactly as the program should receive them. On Windows, a .cmd shim (sf, npm, yarn) refuses an argument with a double quote or line break, or bare shell metacharacters, and a command line over about 7800 characters. Belongs to the Arguments parameter set. Default: @().
-Interactive switch
For a command that asks the person questions, such as sf schema generate field. The output is not stored in a variable, so the command keeps the console and can show its prompts and read the answers, and nothing is parsed. A non-zero exit code throws. Run the calling cmdlet as a plain command: if its output is assigned to a variable or piped, PowerShell captures it and the prompts are hidden. Belongs to the Arguments parameter set.

Example

PS> Invoke-Salesforce -FilePath sf -Arguments @('org', 'list', '--json')

Run sf org list and return its output.

Show-SalesforceResult

Description

Shared helper used by the cmdlets that run sf --json. It parses the output, throws the CLI message (with deploy and test failure details) when the status is not 0, redacts tokens and secrets from error text, and otherwise returns the result property, or only its records with -ReturnRecords. Public because the modules import it from psfdx-shared; it may change without notice.

Syntax

Show-SalesforceResult -Result <psobject> [-ReturnRecords] [-IncludeAttributes]

Parameters

-Result psobject, required
The text the sf command printed (a string or an array of lines). Required.
-ReturnRecords switch
Return result.records (without the attributes property) instead of the whole result. An empty array is returned when there are none.
-IncludeAttributes switch
Keep the attributes property on each record when used with -ReturnRecords.

Example

PS> $raw = Invoke-Salesforce -FilePath sf -Arguments @('org', 'list', '--json'); Show-SalesforceResult -Result $raw

Parse the output of a command.

Test-SalesforceApexTestReference

Description

Returns True if the test file's base name follows Test<ClassName>, <ClassName>Test, or <ClassName>Tests (case-insensitive), or if the contents contain ClassName as a whole word. Does not count partial name matches such as Account within AccountHelperTest. This performs a local file/text check, not an Apex test run.

Syntax

Test-SalesforceApexTestReference -Path <string> -ClassName <string>

Parameters

-Path string, required
Path of the Apex test file (.cls) to examine. The file is read only when its name does not already match a supported test naming convention.
-ClassName string, required
Apex class name to match, either in the test file name or as a whole word in the file contents.

Example

PS> Test-SalesforceApexTestReference -Path './classes/AccountServiceTest.cls' -ClassName 'AccountService'

Returns True based on the test class name.
