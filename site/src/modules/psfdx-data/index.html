MODULE REFERENCE / psfdx-data

psfdx-data

Salesforce data

Query Salesforce with SOQL and SOSL and get PowerShell objects back, create, update, get, delete and upsert single records, upload files, move records between orgs as tree data, and run Bulk API 2.0 jobs from a CSV.

Part of the psfdx package, which installs every module: see the installation and update instructions. This module was psfdx-bulk, and the record and query commands moved here from psfdx; the names and parameters of every command are unchanged.

PS> Get-Command -Module psfdx-data

Commands

Bulk API 2.0

Export-SalesforceBulkData

Description

Give the query as -Query or -QueryFile (a file avoids line breaks, which the Windows CLI shim rejects as an argument). The query is passed to the CLI unchanged. Without -WaitMinutes the job is created and its JobId returned; finish it later with Resume-SalesforceBulkJob -Operation Export. With -WaitMinutes the cmdlet waits and returns TotalSize.

Syntax

Export-SalesforceBulkData -OutputFile <string> [-Query <string>] [-QueryFile <string>] [-ResultFormat <string>] [-AllRows] [-ColumnDelimiter <string>] [-LineEnding <string>] [-WaitMinutes <int>] [-TargetOrg <string>]

Parameters

-OutputFile string, required
File where records are written. Passed to sf as --output-file. Required.
-Query string
SOQL query to execute. Passed to sf as --query.
-QueryFile string
File that contains the SOQL query. Passed to sf as --query-file.
-ResultFormat string
Format to write the results. Passed to sf as --result-format. Default: csv. Valid values: csv, json.
-AllRows switch
Include records that have been soft-deleted due to a merge or delete. By default, deleted records are not returned. Adds --all-rows.
-ColumnDelimiter string
Column delimiter to be used when writing CSV output. Default is COMMA. Passed to sf as --column-delimiter. Valid values: BACKQUOTE, CARET, COMMA, PIPE, SEMICOLON, TAB.
-LineEnding string
Line ending to be used when writing CSV output. Default value on Windows is is `CRLF`; on macOS and Linux it's `LR`. Passed to sf as --line-ending. Valid values: LF, CRLF.
-WaitMinutes int
Time to wait for the command to finish, in minutes. Passed to sf as --wait. Default: 0. Range: 0 to 1440.
-TargetOrg string
Username or alias of the target org. Not required if the `target-org` configuration variable is already set. Passed to sf as --target-org.

Example

PS> Export-SalesforceBulkData -Query 'SELECT Id, Name FROM Account' -OutputFile .\accounts.csv -WaitMinutes 10 -TargetOrg myorg

Get-SalesforceBulkResult

Description

The CLI writes <JobId>-success-records.csv, <JobId>-failed-records.csv and <JobId>-unprocessed-records.csv into its working directory, so the cmdlet runs it in -OutputDirectory (the current directory by default) and returns the full paths of the files it wrote. Records that failed do not make this cmdlet throw: check HasFailures or FailedRecords. A job that has not finished is an error. Works for any job in the org, including ones this computer did not create.

Syntax

Get-SalesforceBulkResult -JobId <string> [-OutputDirectory <string>] [-TargetOrg <string>]

Parameters

-JobId string, required
Job ID of the bulk job. Passed to sf as --job-id. Required.
-OutputDirectory string
Folder the result files are written to. It is created if it does not exist. Defaults to the current folder. The cmdlet runs the CLI there and returns the full paths of the files it wrote.
-TargetOrg string
Username or alias of the target org. Not required if the `target-org` configuration variable is already set. Passed to sf as --target-org.

Example

PS> $r = Get-SalesforceBulkResult -JobId 750xx0000000001 -OutputDirectory .\bulk -TargetOrg myorg; if ($r.HasFailures) { Import-Csv $r.FailedFilePath }

Resume-SalesforceBulkJob

Description

Pass the JobId from the earlier step and the -Operation that created it, or -UseMostRecent for the job the CLI started last. The CLI remembers jobs it created on this computer, so import, update and export resumes find the org from that record; they do not take -TargetOrg (it is ignored with a warning), and a job created elsewhere cannot be resumed here: use Get-SalesforceBulkResult with -TargetOrg instead. Upsert and Delete resumes do take -TargetOrg. Export resumes do not take -WaitMinutes. Resuming only continues the existing job, so it does not ask for confirmation. Errors are as for the cmdlet that created the job.

Syntax

Resume-SalesforceBulkJob -Operation <string> -JobId <string> [-WaitMinutes <int>] [-TargetOrg <string>]
Resume-SalesforceBulkJob -Operation <string> -UseMostRecent [-WaitMinutes <int>] [-TargetOrg <string>]

Parameters

-Operation string, required
The kind of bulk job to resume: Export, Import, Update, Upsert or Delete. It selects which command runs: sf data export, import, update, upsert or delete resume. Required. Valid values: Export, Import, Update, Upsert, Delete.
-JobId string, required
Job ID of the bulk job. Passed to sf as --job-id. Required unless you give -UseMostRecent.
-UseMostRecent switch, required
Resume the job that was started most recently, instead of giving -JobId. Adds --use-most-recent.
-WaitMinutes int
Time to wait for the command to finish, in minutes. Passed to sf as --wait. Default: 0. Range: 0 to 1440.
-TargetOrg string
Username or alias of the target org. Not required if the "target-org" configuration variable is already set. Passed to sf as --target-org.

Example

PS> Resume-SalesforceBulkJob -Operation Upsert -JobId 750xx0000000001 -WaitMinutes 10 -TargetOrg myorg

Runs sf data export resume, sf data import resume, sf data update resume, sf data upsert resume, sf data delete resume.

Tree data

Export-SalesforceTreeData

Description

Each -Query is a SOQL query; a query with a subquery exports parent and children together. The queries go to the CLI unchanged, so use one line and no double quotes (the Windows CLI shim rejects line breaks and double quotes in an argument). Without -Plan the records are returned in Records and the CLI writes one JSON file per query. With -Plan the CLI writes one file per object and a plan file that references them, which Import-SalesforceTreeData -Plan reads; Files and PlanFile hold their paths. The CLI creates -OutputDirectory if it does not exist.

Syntax

Export-SalesforceTreeData -Query <string[]> [-Plan] [-Prefix <string>] [-OutputDirectory <string>] [-TargetOrg <string>]

Parameters

-Query string[], required
One or more SOQL queries whose records, with the related records they select, are exported. Each query is passed as its own --query. A query with a parent-to-child subquery exports the children too. Required.
-Plan switch
Generate multiple sObject tree files and a plan definition file for aggregated import. Adds --plan.
-Prefix string
Prefix of generated files. Passed to sf as --prefix.
-OutputDirectory string
Directory in which to generate the JSON files; default is current directory. Passed to sf as --output-dir.
-TargetOrg string
Username or alias of the target org. Not required if the `target-org` configuration variable is already set. Passed to sf as --target-org.

Example

PS> Export-SalesforceTreeData -Query "SELECT Id, Name, (SELECT Id, LastName FROM Contacts) FROM Account WHERE Name LIKE 'Acme%'" -Plan -OutputDirectory .\data -TargetOrg source
PS> Import-SalesforceTreeData -Plan .\data\Account-Contact-plan.json -TargetOrg scratch

Salesforce CLI

Runs sf data export tree.

Import-SalesforceTreeData

Description

Give either -Plan (a plan file from Export-SalesforceTreeData -Plan) or -File (one or more tree JSON files), not both. Asks for confirmation only when $ConfirmPreference is Medium or lower, and -WhatIf makes no CLI call. Returns one object per record created: RefId, Type and Id. If Salesforce rejects records, nothing is returned and the cmdlet throws PsfdxTreeImportFailed, whose TargetObject lists each failed reference with its StatusCode, Message and Fields. The Tree API imports at most 200 records per call.

Syntax

Import-SalesforceTreeData -Plan <string> [-TargetOrg <string>]
Import-SalesforceTreeData -File <string[]> [-TargetOrg <string>]

Parameters

-Plan string, required
Plan definition file to insert multiple data files. Passed to sf as --plan. Required in the Plan parameter set.
-File string[], required
Comma-separated and in-order JSON files that contain the records, in sObject tree format, that you want to insert. Passed to sf as --files. Required in the Files parameter set.
-TargetOrg string
Username or alias of the target org. Not required if the `target-org` configuration variable is already set. Passed to sf as --target-org.

Example

PS> Import-SalesforceTreeData -Plan .\data\Account-Contact-plan.json -TargetOrg scratch

Runs sf data import tree.

Records and queries

Get-SalesforceRecord

Description

Select the record with -Id, or with -Where, a hashtable of field values that identify exactly one record (the CLI reports an error for none or for several). They are alternatives: the CLI accepts only one. The record is returned as an object of its fields, without the internal attributes property. A value in -Where is passed to the CLI as Field='value'; because the CLI has no way to escape a quote inside a value, a value that contains a single quote, a double quote or a line break is refused. For anything more complex use Select-SalesforceRecords. A record that does not exist makes the cmdlet throw the CLI's message.

Syntax

Get-SalesforceRecord -Type <string> -Id <string> [-UseToolingApi] [-TargetOrg <string>]
Get-SalesforceRecord -Type <string> -Where <IDictionary> [-UseToolingApi] [-TargetOrg <string>]

Parameters

-Type string, required
API name of the Salesforce or Tooling API object that you're retrieving a record from. Passed to sf as --sobject. Required.
-Id string, required
ID of the record you're retrieving. Passed to sf as --record-id. Required in the ById parameter set. Alias: RecordId. Accepts input from the pipeline by property name.
-Where IDictionary, required
List of <fieldName>=<value> pairs that identify the record you want to display. Passed to sf as --where. Required in the ByFields parameter set.
-UseToolingApi switch
Use Tooling API so you can retrieve a record from a Tooling API object. Adds --use-tooling-api.
-TargetOrg string
Username or alias of the target org. Not required if the `target-org` configuration variable is already set. Passed to sf as --target-org.

Example

PS> Get-SalesforceRecord -Type Account -Id 001xx000003DGb2AAG -TargetOrg myorg

Salesforce CLI

Runs sf data get record.

New-SalesforceFile

Description

Runs sf data create file. The file becomes a ContentVersion, so it shows under Files in the org. Give -ParentId to attach it to a record, for example an account. Supports -WhatIf and -Confirm; it does not prompt by default. The file is read by the CLI; psfdx only checks that it exists.

Syntax

New-SalesforceFile -File <string> [-ParentId <string>] [-Title <string>] [-TargetOrg <string>]

Parameters

-File string, required
Path of the local file to upload. Passed to sf as --file. It must exist. Required.
-ParentId string
ID of the record to attach the file to (a 15 or 18 character ID). Passed to sf as --parent-id.
-Title string
Title of the file in Salesforce. By default the CLI uses the file name. Passed to sf as --title.
-TargetOrg string
Username or alias of the target org. Not required if the `target-org` configuration variable is already set. Passed to sf as --target-org.

Example

Search-SalesforceRecords

Description

Runs sf data search with --query or --file. SOSL searches the text fields of several objects at once, for example FIND {Acme} IN ALL FIELDS RETURNING Account(Id, Name), Contact(Id, Name). With the default -ResultFormat json the records are returned as objects without their attributes property, each with an SObject property that holds the object it came from; no match returns nothing (wrap the call in @() for an empty array). With human or csv the CLI text is returned as it is. A bad search throws the CLI message. The query is passed as one argument, so braces and quotes need no escaping; on Windows the CLI shim rejects a double quote or a line break in an argument, so put such a query in a file and use -File.

Syntax

Search-SalesforceRecords -Query <string> [-ResultFormat <string>] [-TargetOrg <string>]
Search-SalesforceRecords -File <string> [-ResultFormat <string>] [-TargetOrg <string>]

Parameters

-Query string, required
SOSL query to execute. Passed to sf as --query. Give -Query or -File.
-File string, required
File that contains the SOSL query. Passed to sf as --file. It must exist. Give -Query or -File.
-ResultFormat string
Format to display the results. Default: json. Valid values: human, csv, json. Passed to sf as --result-format for human and csv; json is read through --json.
-TargetOrg string
Username or alias of the target org. Not required if the `target-org` configuration variable is already set. Passed to sf as --target-org.

Example

PS> Search-SalesforceRecords -Query 'FIND {Acme} IN NAME FIELDS RETURNING Account(Id, Name), Contact(Id, Name)' -TargetOrg dev1

Accounts and contacts whose name matches Acme.

Salesforce CLI

Runs sf data search.

Select-SalesforceRecords

Description

Runs sf data query with --query or --file. With the default -ResultFormat json the records are returned as objects without their attributes property; an empty result returns nothing (wrap the call in @() for an empty array). With human or csv the CLI text is returned as it is. A failing query throws the CLI message. The query text is passed as one argument, so quotes and special characters need no escaping.

Syntax

Select-SalesforceRecords [-Query <string>] [-File <string>] [-TargetOrg <string>] [-UseToolingApi] [-IncludeDeletedRows] [-ResultFormat <string>] [-OutputFile <string>]

Parameters

-Query string
SOQL query to execute. Passed to sf as --query.
-File string
File that contains the SOQL query. Passed to sf as --file.
-TargetOrg string
Username or alias of the target org. Not required if the `target-org` configuration variable is already set. Passed to sf as --target-org.
-UseToolingApi switch
Use Tooling API so you can run queries on Tooling API objects. Adds --use-tooling-api.
-IncludeDeletedRows switch
Include deleted records. By default, deleted records are not returned. Adds --all-rows.
-ResultFormat string
Format to display the results; the --json flag overrides this flag. Default: json. Valid values: human, json, csv.
-OutputFile string
File where records are written; only CSV and JSON output formats are supported. Passed to sf as --output-file.

Example

PS> Select-SalesforceRecords -Query 'SELECT Id, Name FROM Account LIMIT 5' -TargetOrg dev1

Five accounts as objects.

Upsert-SalesforceRecord

Description

The CLI has no single-record upsert command, so this sends a PATCH to /services/data/vXX.X/sobjects/<Type>/<ExternalIdField>/<value> with sf api request rest. The body is written to a temporary file that is removed afterwards. The result says whether the record was Created or Updated and gives its Id when the API returns one.

Syntax

Upsert-SalesforceRecord -Type <string> -ExternalIdField <string> -ExternalId <string> -Fields <IDictionary> [-ApiVersion <string>] [-TargetOrg <string>]

Parameters

-Type string, required
API name of the object, for example Account. Required.
-ExternalIdField string, required
API name of the external ID field used to find the record. Required.
-ExternalId string, required
Value of the external ID. It is URL-escaped in the request path. Required.
-Fields IDictionary, required
Hashtable of field API names and values to set, for example @{ Name = 'Acme' }. It must not be empty. Required.
-ApiVersion string
REST API version to use, for example v62.0 or 62.0. If omitted, the latest version the org supports is used.
-TargetOrg string
Username or alias of the target org. Not required if the `target-org` configuration variable is already set. Passed to sf as --target-org.

Example

PS> Upsert-SalesforceRecord -Type Account -ExternalIdField Ext_Id__c -ExternalId A-100 -Fields @{ Name = 'Acme' } -TargetOrg dev1

Create or update the account whose Ext_Id__c is A-100.

Salesforce CLI

Runs sf api request rest.
