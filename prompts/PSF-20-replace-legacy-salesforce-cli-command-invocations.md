# PSF-20: Replace legacy Salesforce CLI command invocations

**Tracking issue:** https://github.com/tonygward/psfdx/issues/105

Generated by Matrix from the tracking issue when the card was picked up, because no prompt file existed and the issue had enough detail. The issue text below is the specification.

## Objective
Keep existing psfdx cmdlets compatible with the current stable Salesforce CLI without changing their public PowerShell API.

## Scope
- `Retrieve-SalesforceOrg` in `psfdx-metadata/psfdx-metadata.psm1`: migrate `sf force source manifest create` to the supported `sf project generate manifest` equivalent; verify `--from-org`, package inclusion, file output and subsequent retrieve.
- `Get-SalesforcePackagesInstalled` in `psfdx-packages/psfdx-packages.psm1`: migrate `sf force package installed list` to `sf package installed list` preserving target org/API version and return shape.
- `Connect-SalesforceAuthUrl` in `psfdx/psfdx.psm1`: migrate `sf auth sfdxurl store` to `sf org login sfdx-url`, checking exact supported flags and token redaction behaviour.
- Verify the existing CLI installer/updater on macOS: replace outdated `sfdx-cli/tap/sf` Homebrew path with Salesforce-supported instructions.
- Inspect any other `sf force ...` references and migrate only when a confirmed replacement exists.

## Acceptance criteria
- Existing public cmdlet parameters and returned PowerShell objects remain compatible except documented fixes.
- No unverified flag substitutions; check installed stable `sf` help/reference.
- `README.md` and `CHANGELOG.md` describe changes and any migration instructions.
- Windows PowerShell 5.1 and PowerShell 7 support preserved.

## Tests
- Pester exact invocation/JSON mapping tests for each migrated command.
- Smoke-test each command's existence/flags against a current stable Salesforce CLI binary; use a test org where necessary, and never expose secrets.
- Verify Windows, Ubuntu and macOS installer command selection.

## Dependencies and risks
Ensure CLI command availability is established before removing legacy aliases. Non-destructive verification by default.
