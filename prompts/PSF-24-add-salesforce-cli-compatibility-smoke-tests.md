# PSF-24: Add Salesforce CLI compatibility smoke tests

**Tracking issue:** https://github.com/tonygward/psfdx/issues/109

Generated by Matrix from the tracking issue when the card was picked up, because no prompt file existed and the issue had enough detail. The issue text below is the specification.

## Objective
Catch removed commands, renamed flags and JSON contract changes before they break psfdx while retaining mocked Pester tests.

## Scope
- Add a non-destructive test step to validate used `sf` command families and flags against a pinned stable CLI.
- Include modern and legacy invocation checks, especially metadata manifests, package installations, auth, Apex tracing, Jest, lightning dev and deployments.
- Separate offline command-help checks from any opt-in org-backed integration tests.
- Record CLI version and machine-readable compatibility results.

## Acceptance criteria
- PR checks flag incompatible invocations with file/function and suggested replacement.
- CI never requires org credentials for the default verification lane.
- Pin a known stable CLI and support deliberate version refresh, not floating unreviewed breaking updates.
- Human approval for workflow changes under `docs/execution-policy.md`.

## Tests
- Verify correct error reporting when CLI command/flag is absent, and successful handling of aliases that remain valid.
- Ensure no secrets are exposed and Windows/Ubuntu behaviour is covered.
- Document usage and rollback; update CHANGELOG.
