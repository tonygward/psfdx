# PSF-26: Remove Invoke-Expression from shared CLI executor

**Tracking issue:** https://github.com/tonygward/psfdx/issues/111

Generated by Matrix from the tracking issue when the card was picked up, because no prompt file existed and the issue had enough detail. The issue text below is the specification.

## Objective
Eliminate the documented command-injection and quoting risk in `psfdx-shared/Invoke-Salesforce.ps1` without breaking existing wrappers.

## Scope
- Replace `Invoke-Expression -Command $Command` with explicit executable plus argument-array invocation for `sf` and supported auxiliary commands.
- Migrate call sites incrementally, preserving `-Verbose`, result parsing and non-JSON commands.
- Handle SOQL, filenames, nested quotes, whitespace, Unicode, platform-specific native argument parsing, and sensitive auth parameters without shell interpolation.
- Update `CLAUDE.md`, `AGENTS.md` and `.claude/rules/cmdlets.md` so new cmdlets follow the safe pattern.

## Acceptance criteria
- No external input reaches a shell expression interpreter.
- Existing public cmdlets work consistently across Windows PowerShell 5.1, PowerShell 7 and Linux.
- No secret-bearing values echoed to verbose output.
- No regression to the published cmdlet interface; document necessary internal migration.

## Tests
- Pester cases for injection metacharacters, quotation, file paths, SOQL apostrophes and argv fidelity.
- Offline integration tests with a harmless fake executable to capture exact argv across operating systems.
- Verify special CLI format handling (JSON, human and CSV).
