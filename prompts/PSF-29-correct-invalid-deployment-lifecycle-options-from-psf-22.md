# PSF-29: Correct invalid deployment lifecycle options from PSF-22

**Tracking issue:** https://github.com/tonygward/psfdx/issues/140

Generated by Matrix from the tracking issue when the card was picked up, because no prompt file existed and the issue had enough detail. The issue text below is the specification.

## Objective

Correct the two Salesforce CLI compatibility defects identified by the post-merge Codex review of PSF-22 / PR #138, so the new deployment lifecycle cmdlets generate commands accepted by the current stable Salesforce CLI.

## Evidence

Source pull request: https://github.com/tonygward/psfdx/pull/138

The review identified:

1. `Resume-SalesforceDeploy -TargetOrg` emits `sf project deploy resume --target-org ...`, but `sf project deploy resume` does not support that flag. The CLI resumes from the cached deployment and obtains the org from the deployment record.
2. `Test-SalesforceDeploy -TestLevel NoTests` produces `--test-level NoTestRun`, but `sf project deploy validate` requires tests and does not accept `NoTestRun`.

Relevant Salesforce CLI sources:
- Resume implementation: https://github.com/salesforcecli/plugin-deploy-retrieve/blob/main/src/commands/project/deploy/resume.ts
- Deploy validate documentation: https://github.com/salesforcecli/plugin-deploy-retrieve/blob/main/README.md#sf-project-deploy-validate

## Scope

- Remove the unsupported `TargetOrg` parameter and `--target-org` generation from `Resume-SalesforceDeploy`.
- Restrict `Test-SalesforceDeploy -TestLevel` to the validation-supported values:
  - `RunAllTestsInOrg`
  - `RunLocalTests`
  - `RunSpecifiedTests`
  - `RunRelevantTests`
- Ensure `RunSpecifiedTests` still requires and correctly emits the specified Apex tests.
- Review the other PSF-22 lifecycle wrappers against the current stable CLI help for the same class of invalid flag or option error; fix only confirmed defects.
- Update README and CHANGELOG with the corrected behaviour. Treat removal of options that never worked as corrective compatibility fixes.

## Acceptance criteria

- `Resume-SalesforceDeploy` never emits `--target-org` and exposes no misleading `TargetOrg` parameter.
- `Test-SalesforceDeploy` rejects `NoTests` during parameter validation before invoking Salesforce CLI.
- Every accepted validation test level maps to a CLI-supported value.
- Existing report, quick deploy, resume and cancel behaviour remains compatible.
- Windows PowerShell 5.1 and PowerShell 7 support is preserved.
- The release notes clearly identify both PSF-22 corrections.

## Tests

- Pester exact-command tests proving resume emits no target-org flag.
- Pester parameter-validation test proving `NoTests` is rejected for deployment validation.
- Tests for all four supported validation test levels.
- Tests for `RunSpecifiedTests` with valid and missing test names.
- Non-destructive verification against current stable `sf project deploy resume --help` and `sf project deploy validate --help`; no live deployment is required.

## Release expectation

Patch release correcting v0.8.4 deployment lifecycle wrappers.
