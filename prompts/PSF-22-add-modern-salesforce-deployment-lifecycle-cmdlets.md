# PSF-22: Add modern Salesforce deployment lifecycle cmdlets

**Tracking issue:** https://github.com/tonygward/psfdx/issues/107

Generated by Matrix from the tracking issue when the card was picked up, because no prompt file existed and the issue had enough detail. The issue text below is the specification.

## Objective
Expose modern `sf project deploy` lifecycle functionality as PowerShell-friendly wrappers, beyond the existing `deploy start` usage.

## Scope
- Add wrappers for validation, quick deploy, report/status, resume and cancel when supported by current stable CLI.
- Reuse existing `psfdx-metadata` conventions for target org, wait, job IDs, JSON parsing, `-Verbose`, and compatible result objects.
- Respect `ShouldProcess` for destructive actions, especially cancel/deploy as appropriate.
- Avoid duplication with existing `Deploy-SalesforceMetadata` and `Deploy-SalesforceComponent`.

## Acceptance criteria
- Stable cmdlet names and exported manifest entries; README examples demonstrate validate -> quick deploy and resume/report.
- Correct errors when job IDs are missing/invalid, deployments fail or CLI outputs vary.
- No unattended deployment to production during tests.
- Update CHANGELOG and support PowerShell 5.1 and 7.

## Tests
- Pester covering each option, success/failure JSON, job IDs and `ShouldProcess`.
- Test exact command/flag availability using current stable Salesforce CLI.
