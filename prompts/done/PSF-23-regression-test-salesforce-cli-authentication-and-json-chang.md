# PSF-23: Regression-test Salesforce CLI authentication and JSON changes

**Tracking issue:** https://github.com/tonygward/psfdx/issues/108

Generated by Matrix from the tracking issue when the card was picked up, because no prompt file existed and the issue had enough detail. The issue text below is the specification.

## Objective
Protect psfdx against Salesforce CLI changes to authentication and JSON return fields, including recent changes to sensitive value exposure.

## Scope
- Review `Connect-SalesforceAuthUrl`, `Get-SalesforceConnections`, `Connect-SalesforceJwt` and shared `Show-SalesforceResult` handling.
- Confirm the current stable CLI's auth response schema and whether token/URL retrieval requires a dedicated opt-in command.
- Ensure secrets are never logged by `-Verbose`, errors or tests; keep `-IncludeToken` explicit and secure.
- Preserve non-auth command result behavior.

## Acceptance criteria
- No assumptions that access tokens, passwords, or auth URLs exist in ordinary `sf --json` responses.
- No accidental secrets in logs or exception text.
- Document any changed public behaviour with migration guidance.

## Tests
- Mock old/new CLI response shapes and absent sensitive fields.
- Negative and redaction tests; require real-CLI smoke verification without printing credentials.
- Pester on Windows PowerShell 5.1 and PowerShell 7.
