# PSF-31: Accept Metadata API ZIPs in Test-SalesforceDeploy

**Tracking issue:** https://github.com/tonygward/psfdx/issues/148

Generated by Matrix from the tracking issue when the card was picked up, because no prompt file existed and the issue had enough detail. The issue text below is the specification.

## Objective

Let users validate a Metadata API ZIP with `Test-SalesforceDeploy`, matching the Salesforce CLI input support.

## Compatibility gap

`Test-SalesforceDeploy -InputDir` currently uses `Test-Path -PathType Container`. Existing Metadata API ZIP files therefore fail local validation even though Salesforce CLI accepts them through `sf project deploy validate --metadata-dir`.

```powershell
Test-SalesforceDeploy -InputDir ./mdapi.zip -TargetOrg my-org
```

See the [wrapper's path validation](https://github.com/tonygward/psfdx/blob/main/psfdx-metadata/psfdx-metadata.psm1#L643-L659) and [Salesforce CLI command reference](https://developer.salesforce.com/docs/platform/salesforce-cli-reference/guide/cli_reference_project_deploy_validate.html).

## Scope

Change the `-InputDir` validation in `psfdx-metadata/psfdx-metadata.psm1` to accept an existing directory or ZIP. Update the README cmdlet row and changelog.

## Acceptance criteria

- Accept an existing Metadata API ZIP through `-InputDir` and forward it as a single `--metadata-dir` value. Preserve directory inputs, `-ManifestPackage` behavior and input exclusivity.
- Give a clear error for a missing path or an unsupported file type.
- Add Pester coverage for a ZIP path containing spaces, an existing directory and invalid inputs. Exercise command generation without contacting an org.
- Update cmdlet documentation and the changelog.

## Tests

Use Pester to verify exact CLI arguments for a ZIP path with spaces and a directory. Cover missing and unsupported paths, `-ManifestPackage`, and input exclusivity without contacting an org.
